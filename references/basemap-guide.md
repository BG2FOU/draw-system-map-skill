# 底图绘制：行政区与自然地理

本页给出通用示意底图的绘制方法与 `basemap` 数据契约。几何、样式、裁切和独立地理标签均已实现。可直接复制文末两份虚构模板运行。

## 先确定地理关系，再简化轮廓

1. 收集可信的海岸、河道、岛屿和行政区资料，记录来源及名称。区分示意轮廓与测绘边界；无法确认的内容保留待确认，不依据地名猜测行政归属。
2. 沿用线网坐标，先标记跨水段、上岸点、河口和岛屿所在侧。站点坐标不随底图美化改变；海峡应保持连通，桥/隧道两端应落在正确陆块。
3. 提取轮廓关键点。折线风格使用少量稳定方向；曲线用 Q/C 控制点调整，不对所有点盲目平滑。弯曲越明显的岸线保留越多控制点；缩小查看时仍应能辨认主要岛屿、河口和分汊。
4. 自然地理与行政范围分别建模。海岸线不是行政边界；共享行政边界单独建一个要素，不给相邻行政面同时描边。
5. 在区域留白内布置独立标签，降低字号和对比度，避开站名及换乘节点。长区域名可显式分行，不通过移动车站解决重叠。
6. 查看全图以及海峡、岛屿、河口、跨区线路的局部。将修订写回源 JSON，再导出；在编辑器中的临时改动不会自动回写。

可使用参考图、已有 SVG 或 GIS 资料辅助整理坐标。本工具直接绘制画布坐标，不执行地理投影、在线取图、自动配准或自动拓扑修复；不把示意图标成精确地理底图。

## 顶层与要素

`version: 1` 增加可选 `basemap`；省略时现有 SVG 行为不变。旧 `regions` 在新底图之前绘制，旧 `annotations` 层级保持原样。

```json
{
  "basemap": {
    "frame": [30, 100, 900, 600],
    "background": "#dceef6",
    "features": [],
    "labels": []
  }
}
```

- `frame` 必填，采用 `[x,y,width,height]`，宽高大于 0，整个矩形在画布内。所有底图、边界和地理标签均裁切到此框；标题和图例需要在框外留白，或用图例底板隔开。
- `background` 可选，常用于海域底色；省略则透出旧背景/画布。
- `features` 必填数组；`labels` 可省略。`styles` 可按下表的 `kind` 覆盖全局底图样式。

| 要素 `kind` | 几何 | 默认层/表现 |
| --- | --- | --- |
| `land` | area | 陆地层，浅米白填色 |
| `island` | area | 陆地层，独立岛屿填色；不要求名称或标签 |
| `admin` | area | 行政填色层，浅色无描边，显式指定裁切范围 |
| `water` | area | 水域层，用于湖泊、湾区和宽水面 |
| `river` | line 或 area | 水域层，窄河用中心线及线宽，宽/变宽/分汊河用闭合水面 |
| `boundary` | line | 边界层，细灰色虚线；共享边界只绘一个要素 |
| `coastline` | line | 边界层，细浅灰实线；与行政边界分开设置 |

每个要素包含 `id`、`kind`、`geometry`。`id` 在底图内唯一，使用英文字母开头的字母/数字/下划线/短横线，便于稳定 SVG 标识。可选 `name`、`source` 为文字元数据，`source` 可记录出处、日期或“虚构示例”；不会自动抓取来源。

`order` 为有限数字，默认 0；只在同一层内控制先后，数值越大越晚绘制，同值按输入顺序。`visible: false` 隐藏要素及关联标签，但它的几何仍可被 `clip_to` 引用。

最终叠放：旧背景 → 底图背景 → 陆地/岛屿 → 行政填色 → 水域/河流 → 边界/海岸 → 地理标签 → 线路与站点/站名。稳定 SVG 组为 `basemap-land`、`basemap-admin`、`basemap-water`、`basemap-boundary`、`basemap-labels`；每个要素组标注 `data-feature` 和 `data-kind`。

## 几何：曲线、多面与孔洞

路径是指令数组；仅接受绝对坐标 `M/L/Q/C/Z`，不接受任意 SVG 字符串。

| 指令 | 数组形式 |
| --- | --- |
| 起点 | `["M",x,y]`，每条路径只能在开头出现一次 |
| 直线 | `["L",x,y]` |
| 二次曲线 | `["Q",cx,cy,x,y]` |
| 三次曲线 | `["C",c1x,c1y,c2x,c2y,x,y]` |
| 闭合 | `["Z"]`，只允许在结尾 |

所有坐标必须有限。每条路径至少有一个有效绘制段；面轮廓须显式用 Z 闭合，不能靠起终点重合代替。直线面至少三个不同顶点；曲线面允许两个不同锚点和曲线围成区域。工具检查结构和明显退化，不计算任意曲线的自交、孔洞包含或完整拓扑。

```json
{
  "type": "area",
  "parts": [{
    "outer": [["M",100,120],["L",700,120],["C",760,180,760,400,700,480],["L",100,480],["Z"]],
    "holes": [[["M",300,220],["L",420,220],["L",420,320],["L",300,320],["Z"]]]
  }]
}
```

`parts` 至少一个面，每面有 `outer` 和可选 `holes`。每个面以独立复合路径、`evenodd` 填充，内环透出下层；多个面重叠时取其绘制覆盖，不把独立面的重叠部分错误镂空。孔洞须在对应外环内部且不能互相重叠，此关系需查看实际图形。

湖中岛/河中洲建议用“下层陆地或岛屿 + 上层水面孔洞”：水面孔洞透出已绘制的陆地及行政填色。如果岛上还有湖，再增加更高 `order` 的水面。岛与陆地分离的外海场景，直接使用海域背景加多个陆地面。不能仅依赖把 `island` 放在数组末尾来盖住上层水面。

线几何用于河流、行政界和海岸：

```json
{"type":"line","paths":[[["M",200,130],["Q",230,250,350,350],["C",390,390,430,450,460,510]]]}
```

`paths` 至少一条，线不会自动闭合。闭合行政边界可显式使用 Z。窄河宽度为画布单位，来自输入；河流支线作为同一要素的多条路径绘制，汇合点共享坐标。宽河道和洲岛用 area 及 holes，不从中心线猜测真实岸线。

## 行政填色与共享边界

`admin` 必须显式写 `clip_to`：非空陆地/岛屿 ID 数组，或 `null` 表示有意保留完整行政面（例如包含水域的范围）。其他类型不接受 `clip_to`。裁切范围为引用面几何的并集，包含各面的孔洞；生成器按显式外环/内环角色统一裁切路径的绕向，使用 nonzero 规则，避免部分渲染器将多面重叠误作孔洞；可引用暂时隐藏的陆地几何。重复 ID、未知 ID、引用非陆地/岛屿要素都报错。

```json
{
  "id":"north-district", "kind":"admin", "name":"北区",
  "clip_to":["mainland","river-island"],
  "geometry":{"type":"area","parts":[{"outer":[["M",30,100],["L",650,100],["L",650,360],["L",30,360],["Z"]]}]},
  "style":{"fill":"#ede7dc"}
}
```

河湖后绘制会覆盖行政填色；需要表达水上行政界时使用独立 `boundary`。相邻区的共享边线只定义一个边界要素；生成器不自动寻找相邻面或删除重复几何。重复的要素 ID 会被拒绝，不代表已经完成几何去重。

## 样式与地理标签

`basemap.styles.<kind>` 为类别默认样式，单要素 `style` 优先。样式字段：`fill`、`stroke`（颜色或 `"none"`）、`stroke_width`（非负）、`opacity`（0–1）、`dash`（正数数组，空数组为实线）。颜色沿用工具的色值格式。线不填色；河流中心线默认宽 12，边界默认宽 1.2，海岸默认宽 1。面积和线的语义不从颜色推断。

标签由 `basemap.labels` 声明，必须关联已有 `feature`，`id` 在标签中唯一：

```json
{
  "id":"north-name", "feature":"north-district", "point":[300,210],
  "text":"北区", "secondary_text":"North District",
  "anchor":"middle", "size":22, "secondary_size":14,
  "color":"#7b8991", "opacity":0.8, "line_height":26
}
```

`id/feature/point/text` 必填；主文字中的换行显式分行，`secondary_text` 为可选第二语言。默认 `anchor: middle`、`size: 22`、`secondary_size: 14`、`line_height: size*1.25`、`color: #7b8991`、`opacity: 0.85`，继承全图字体。标签不自动移动或附加译名；关联隐藏要素的标签不绘制。

## 验收

- 源数据：要素类型、名称、来源、共享边界和跨水关系正确；旧输入仍可用。
- 几何：孔洞不被填死，多面不互相挖洞；行政色不溢出指定陆地；河口、分汊和海峡保持连通。
- 版式：查看全图与局部，区域名不遮站名，底图显著度低于线路；画框裁切不吞掉所需标注。
- 编辑性：路径、复合路径和文字保持独立可编辑；SVG 图层稳定，不嵌入整图位图。

`--check` 只检查源与产物是否一致。自动校验不证明地理准确或布局无碰撞；渲染后检查是交付的一部分。

## 可运行示例

- [沿海群岛源数据](../assets/coastal-basemap-network.json)：大陆、双岛、多面礁群、曲线岸线、行政共享边界和跨海线路。[预览](../assets/previews/coastal-basemap.png)。
- [内陆河谷源数据](../assets/inland-basemap-network.json)：两行政区、变宽河道、支汊、湖中岛与岛上池塘，展示多层嵌套和裁切。[预览](../assets/previews/inland-basemap.png)。

在 skill 根目录运行：

```bash
python3 scripts/draw_map.py assets/coastal-basemap-network.json --output output/coastal.svg
python3 scripts/export_png.py output/coastal.svg output/coastal.png --scale 1.5
python3 scripts/draw_map.py assets/inland-basemap-network.json --output output/inland.svg
python3 scripts/export_png.py output/inland.svg output/inland.png --scale 1.5
```

河谷示例的关系是：大陆外环中的湖泊孔洞 → 独立湖心岛 → 带岛孔洞的湖水面 → 更高 `order` 的岛上池塘。行政区裁切同时引用大陆和湖心岛；湖水不会盖住岛，池塘也不会抹去整块岛。
